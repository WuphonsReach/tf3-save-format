# Tools

Small read-only Python scripts used to check the notes in `docs/`. They are reference code, not a supported product: no releases, no promise they work on your saves. Bug reports with evidence (format version, what you saw) are very welcome. We aren't taking feature requests for the scripts, sorry.

Python 3.14 or later, standard library only (older Python works with the `zstandard` package installed), except `town_centre.py`, which also needs numpy and Pillow (both permissively licensed, imported at run time, not bundled).

None of these scripts write a save. For editing, see [tf3-save-editor](https://github.com/TBK/tf3-save-editor).

| Script | What it does |
|---|---|
| `tf3save.py` | Shared code: zstd helpers, the empty trailing frame, temperate cargo ids, `scan_records` (the town record scan), `cargo_entries` and `cargo_list` (the save's own cargo list, which gives the cargo ids), the calendar speed field and day table, a Lua value reader and `script_state(stream, path)`, and the New Game option labels (`setting_label`). Imported by the others |
| `save_header.py SAVE.sav [...]` | Print a save's header: version, start year, map size, money, counter, preview, mods, resources, a few settings. Importable as `read_header(path)` |
| `calendar_speed.py SAVE.sav [...]` | Print the calendar speed (`millisPerDay`), play speed and current day stored in a save. Importable as `tf3save.find_game_speed(stream)` and `find_day_table(stream)` |
| `items_lists.py SAVE.sav (--cargo ID \| --list REGEX) [--periods N]`, `--table LABEL=OFFSET:LIST ...`, `--entries OFFSET:LIST` | Read the `items*` statistics lists ([docs/statistics-lists.md](../docs/statistics-lists.md)): per group, each matching list's total, last entry time (and how many 1,461,000-unit periods before the save's clock), and its change in each of the last N periods with trailing zeros kept, so a stage that stopped shows as zeros; a per-period table across named lists; one list's entries. `--stream` takes an already decompressed stream. Offsets are stream offsets and move between saves; groups are matched by figures, since their owner is not known. Used in [docs/analysis-examples/](../docs/analysis-examples/CLAUDE.md) |
| `notifications.py SAVE.sav [--type REGEX] [--since CLOCK] [--last N] [--open] [--json]`, `--summary`, `--lines` | List the entries of the notifications state ([docs/notifications.md](../docs/notifications.md)), oldest first: id, clock, type, flags (dismissed, expired, tracked, persisting), entity ids, the names kept in `simParams`, and the other params. `--summary` counts entries per type and the bookkeeping tables; `--lines` lists the line entities that `line_warning` entries name (entity, `lineName`, whether the line is a key of `line2problemTimestamp`, `lineProblem`, `lineIssues`). `--stream` takes an already decompressed stream. Importable as `read_notifications(data)` and `entries(state)`. A string that looks like a path is masked. Used in [docs/analysis-examples/](../docs/analysis-examples/CLAUDE.md) |
| `town_states.py SAVE.sav [...]` | Print the per-town rating state from the `townStates` table |
| `street_edges.py SAVE.sav [--near X,Y,R] [--type REGEX] [--nodes] [--ids] [--json]`, `--diff OLD NEW` | List the street edges ([docs/road-network.md](../docs/road-network.md)): end node ids, end positions, street or track type and length per edge, or per node; `--ids` adds each edge's entity id where the strip table has an entry; `--diff` compares two saves and prints the edges added, removed or changed. Importable as `read_edges(data)`, and `read_free_ids(data)` (the set of the save's free entity ids, or None; [docs/town-leftovers.md](../docs/town-leftovers.md)) |
| `industry_compass.py SAVE.sav OUT.svg [--top N] [--across N] [--down N] [--no-sun]` | Test the compass words in industry and building names ([docs/compass.md](../docs/compass.md)): for each name ending in North, South, East or West, count the same-kind industries, depots and boathouses near that town in the quarter the word names, under each of eight frames of x and y, and draw one picture per town (2 across and 3 down by default, the most telling towns first), with the surest N names (4 by default) drawn, the named industries in blue and the other same-kind ones hollow, against the town's centre (the game's frame, orange sunrise and sunset icons from `icons/`). The town centre is the mean of its street nodes. A PNG is a browser screenshot of the SVG |
| `parcels.py SAVE.sav [--near X,Y,R] [--json] [--points]`, `parcels.py --diff OLD.sav NEW.sav [--near X,Y,R]` | List the parcel table ([docs/parcels.md](../docs/parcels.md)): without options a summary (where the table starts, parcels, street edges, faces, how often each flag word and tail value occurs); `--near` one line per parcel with its first face near the point (table index, street edge id, side, position along the edge, the flag word of each face, centre of the first face); `--json` the same as JSON, `--points` with the corners of every face. `--diff` compares two saves of one game by table index and prints the parcels whose flag words changed, the number of parcels appended and, with `--near`, only those near a point. Importable as `read_parcels(data)`. `--stream` reads an already decompressed stream. Takes under a second on a 150 MB stream. The parcel's own entity id is not in the table, so it prints the index |
| `town_centre.py SAVE.sav --list`, `town_centre.py SAVE.sav --town X,Y SHOT.png [...] [--out DIR] [--json] [--scales A,B,..] [--pitches A,B,..] [--thorough] [--min-score S] [-j N]` | Find a town's centre from a series of screenshots of its name label ([docs/town-centre.md](../docs/town-centre.md)): registers each picture to the save's street edges (heading, zoom, pitch, perspective), maps the label's bottom-edge middle to metres, and fits a circle and a label-at-a-height model through the series. `--list` names the town street clusters to pick `--town` from. Needs numpy and Pillow; reads a save and pictures, writes only into `--out` (a picture and a JSON) |
| `model_instances.py SAVE.sav [--near X,Y,R] [--prefix PATH] [--stream]` | List the model instances ([docs/models.md](../docs/models.md)) whose model path starts with `--prefix` (default `vehicle/`): slot, model, position and facing (the first row of the transform). Importable as `read_model_table(data)` and `read_instances(data, prefixes)`. Reads the whole stream (about 20 s for 700 MB). A vehicle's name and entity id are not next to its instance, so a vehicle is named by model and slot; the slot is only good within one save |
| `terrain_map.py OUT_DIR SAVE.sav [...] [--mpp M] [--crop X,Y,R] [--grid N] [--grid-lines auto\|none\|dots\|faint] [--grid-dot-step M] [--png \| --raster] [--contour M] [--index N] [--no-bands] [--tolerance M] [--no-grid] [--no-industries] [--rose WHERE] [--rose-size M] [--north game\|sun] [--game DIR] [--no-network] [--keep-dead] [--depots] [--coverage] [--industries] [--industry-size M]` | Draw the heightmap with the street-edge table's roads and rails on top ([docs/terrain.md](../docs/terrain.md#drawing-the-map)). An edge with an end node in the save's free-id list (a deleted town's or road's leftover, [docs/town-leftovers.md](../docs/town-leftovers.md)) is left out unless `--keep-dead` is given; the run prints how many were dropped. The default output is an SVG: the terrain (height ramp, hill shading, water) as an embedded PNG, and the roads (grey) and rails (red) as vector paths in map metres, in layers a page script can toggle: every layer is a `g.layer` with its id in `data-layer`, roads and rails have a sublayer per type with one `<path data-a data-b>` per edge, vehicles one sublayer per class with a `<g class="vehicle" data-slot data-model data-class>` each, labels and end nodes their own sublayers (the full list is in the script's docstring). Line widths are in metres, so they scale with the terrain in any viewer, and as wide as the street or track type's profile (the sum of its lanes' widths, a small town street 16 m, a track 4 m, read from the install's templates at run time, with 16 and 4 m for a type it lacks; `--game DIR` names the install, otherwise the usual Steam folders are tried; `--min-width M` sets a floor in metres so a whole-map picture keeps its tracks visible). Output names have no spaces, and a crop's name carries its centre and radius. The SVG's `<metadata>` holds one `tf3map:view` element (namespace `urn:tf3-save-format:terrain-map:1`) with the save's file name, the map size, the metres per pixel, the map point at the picture's top-left corner, the x and y range it covers, the crop and the grid step, and which run made it (`generator`, `generator-commit`, the last commit that changed a `tools/*.py` with `-dirty` if one has uncommitted changes, and `generated-utc`; a setting left at its default is not recorded, only one changed from it), so a picture can be turned back into map coordinates without its command line. `--png` writes one flat shaded PNG instead, with the same view record in an `iTXt` chunk `tf3map:view` (a UTF-8 JSON object with the SVG attribute names, `north` included). The terrain is vector by default ([terrain_vector.py](terrain_vector.py); output `...-terrain.svg`, `--mpp` default 8, 4 on a crop): sublayers `land`, `bands` (a path per `--contour` metres of height, default 20, filled from a height ramp, each covering all ground from there up), `water` (lakes, sea and rivers as one even-odd path, from the contour at the water level) and `contours-minor` / `contours-index` (one `<path data-height>` per level, every `--index`th heavier, default 5, thinned to `--tolerance`); `--no-bands` leaves the fills out. There is no hill shading, so the file is hundreds of kilobytes where a raster one is megabytes; roads, rails, vehicles and grid go on top as before. A compass rose (a white circle, black arrow and E, S, W arms, in the shape of `icons/compass_rose.svg`) sits in its own top `compass` layer, lower left by default: `--rose lower-right|upper-left|upper-right|off|X,Y` moves or removes it, `--rose-size` sets its diameter (250 m, at most an eighth of the picture's short side), and its arms follow `--north`. `--raster` draws the old terrain, a shaded PNG embedded in the SVG (`...-terrain-raster.svg`). `--mpp` is the terrain's metres per pixel, a multiple of 4, default 4 (the grid's own spacing); a picture over 64 million pixels is refused until `--mpp` is raised (the 20 x 41 km Giant map is 52 million at 4 m: 42 s, 1.3 GB, an 81 MB SVG). The SVG has a grid by default, major marks only: a large cross where the lines meet, a dotted line and a label at each, every third of the picture's shorter side rounded down to 1, 2 or 5 times a power of ten (a whole map at least 1000 m, so Tiny and Small get 1 km, Medium and Large 2 km, Giant 5 km; a `--crop` has no floor), `--no-grid` leaves it out. `--grid N` (SVG only) adds minor marks, for fine work, in the same `grid` layer, so a place seen in the picture can be turned into `--crop` coordinates: a small violet cross where the lines at every multiple of N metres of map x and y would meet (sublayer `grid-minor`), a larger one where two 1000 m lines meet, a line of darker dots at each multiple of 1000 m (both in `grid-major`; every dot and small cross arm is one pixel wide, a large cross's arm 1.5), and coordinate labels along the top and left in a `grid-labels` layer over everything. The marks are violet because no terrain, road or rail colour is near it, and crosses and dots do not read as roads the way solid lines do. `--grid-lines none` leaves out the dotted 1000 m lines, and so does the default `auto` on a picture of 1 m per pixel or finer, where a dot is a speck and the crosses are enough; `--grid-lines dots` also draws the minor lines as round dots every `--grid-dot-step` metres (default 25, never closer than 10 pixels, and nudged so a whole number fit between two crosses; a small cross's arm is a sixth of the gap, a larger cross's 0.4 of it, and the 1000 m lines carry twice as many dots; `--mpp 2` on a crop allows 25 m), and `--grid-lines faint` as thin faint solid lines. `--label A>B[=TEXT]` (repeat; SVG only) adds a `labels` layer naming just the edges asked for by their end node ids in hex (`2a619>342aa`), above the vehicles, each in its own light colour (the text's halo) with a white dot, black ring, at both ends (a node shared by two labelled edges gets a dot of two halves, one in each edge's colour, the half toward its edge); `--edge-ids` adds the edge's entity id where the strip table has one. `--vehicles` (needs `--crop`) adds a `vehicles` layer: each `vehicle/` model instance as a five-sided shape (a rectangle with a pointed front end, white outline, mid-dark grey for trains and trams; interior dark orange for a train engine, light orange for its trailing cars, purple tram, dark blue truck, dark green bus, dark grey ship, mid grey car), sized by class, with text only where `--name SLOT=TEXT` gives it (a default name is shortened: `Road Vehicle 279` is `RV279`, `Train 58` `RR58`, `Ship 106` `S106`, `Tram 62` `TRM62`, `Aircraft 6` `AIR6`) (the run prints every instance drawn with its slot, so a second run can name them). `--depots` (SVG only) adds `maintenance-buildings`, `road-depots`, `tram-depots`, `rail-maintenance-buildings`, `rail-depots`, `ship-maintenance-buildings`, `ship-depots` and `boathouses` layers: each building as its ground face (one colour per carrier, provisional: road orange, tram purple, rail teal, ship pink; black outline; a boathouse of the Boathouse mod has no face, only the dot and line), origin dot and a line along the model's x axis, placed from the instance's origin and facing ([docs/models.md](../docs/models.md#road-maintenance-buildings-and-depots-origin-facing-footprint-and-coverage)); `--coverage` adds a `coverage` layer under the roads with a dashed circle per building at the script's catchment radius (sublayers per kind, `data-pool` and `data-modes` on each). Both read the footprint, radius and pool from the install's `depots/road.zip` at run time (without an install nothing is drawn), need no `--crop`, and leave out aircraft maintenance; the boathouse's radius and pool are read from the mod's folder (`--mods DIR`, default the usual mod.io places), and the free Boathouse asset shares its model. `--industries` (SVG only, on by default; `--no-industries` leaves it out) adds an `industries` layer: each industry as a white disc with a grey border and its icon from `icons/industries/` in dark grey, centred on the origin of its main model (a sublayer per key, `<g class="industry" data-slot data-key data-x data-y>` each). The disc is 96 m across by default and `--industry-size M` sets another diameter (the icon and border scale with it). The real footprint is not read, so a badge may overhang a small industry; it is a few pixels on a whole-map picture, so zoom in. `--zoom N` opens the SVG N times larger. `--crop X,Y,R` draws only the square of half-width R metres around a map point, and with it `--mpp` may be 1 or 2 (terrain interpolated). Writes only the picture. A sample picture: [docs/samples/terrain-map-area-labelled-6425796.svg](../docs/samples/terrain-map-area-labelled-6425796.svg) |
| `terrain_vector.py` (library, no command line) | Marching-squares contours of a heightmap grid for `terrain_map.py`: `level_rings` (closed rings round the ground below the water level and below every multiple of a step above it, the grid padded so rings close at the picture's edge, for even-odd filling), `split_at_border` (a ring back into open height lines), `simplify` (Douglas-Peucker, tolerance in metres) and `path_data` (SVG path text, tenths of a metre). Points are metres from the picture's top-left corner, the frame the road layers use. Standard library only. |
| `schema/tf3-save-summary.v<N>.schema.json` | JSON Schema (draft 2020-12) of the summaries `mine_saves.py` writes, one file per `schema_version`: every field, its meaning, when it is null, and the `"3 (100%, default)"` labels. Any change to the layout gets a new version and a new file; a committed schema file is never edited, so a summary's `$schema` link keeps matching it |
| `check_links.py [REPO_ROOT]` | Check the repo's Markdown files: relative links and `#anchors` that point nowhere, notes in `docs/` missing from `docs/README.md`, scripts missing from this table. Reads no saves. Exit status 1 when it reports anything |
| `facts_index.py [REPO_ROOT] [--max-words N] [--max-section-words N] [--outline NOTE [--bullets]]` | Outline the notes in `docs/`: words, headings, links in and out per note, biggest first, with a mark on notes over the word limit (default 3500) as split candidates, then the sections over 1500 words. `--outline docs/NOTE.md` lists that note's headings with line numbers and the words under each, so one section can be opened and not the whole note; `--bullets` adds a row per paragraph or bullet (line, words, first words), enough to regroup a long section without reading it. Run it before a split or a consistency pass. Reads no saves |
| `find_dupes.py [REPO_ROOT] [--note NOTE] [--kind code\|number] [--where TERM] [--prose] [--since REV]` | Find what more than one note in `docs/` mentions: code spans and numbers of four or more digits shared by 2 to 6 notes (test save names left out), the pairs of notes sharing the most, and the pairs sharing terms with no link between them. `--note` keeps what involves one note; `--where TERM` lists every line with the term, its note and heading. `--prose` finds the same wording in two notes (runs of eight words). `--since REV` compares with `docs/` at an older revision: shared terms before and after (a split's new note counted with the note it came from), terms in more notes than before, and links that name a term their target note has lost. A shared term is a lead, not a defect: pointers to a home note share terms with it, and a split raises the count. Reads no saves |
| `lint_docs.py [REPO_ROOT] [--since REV]` | Check a change to `docs/` before committing it (the working tree against `HEAD`, or against an older revision for a series of commits). Errors, exit status 1: anything `check_links.py` reports, a note or section that crossed its word limit, a link to a note that lost the term it names. Warnings, on the changed lines only: the same wording in two notes, terms in more notes than before, notes that share terms without linking. One line per finding. Reads no saves |
| `glossary_check.py [REPO_ROOT] [PATH ...] [--since REV] [--stdin] [--summary] [--ambiguous] [--word W] [--include-quoted]` | Point out where a note says a player's word or an on-screen label ("concrete", "canning factory", "trawler", "truck stop") and the game's key (`cement`, `food_factory`, `ship`, `small_*`) should be used. The word lists come from the tables in [docs/glossary.md](../docs/glossary.md), so that note is the one place to fix. Skips code spans, link targets, quoted text, a capitalised word in mid-sentence (proper names), a word inside a longer key or label ("sheet metal", "road stop") and a word with its key in code font beside it; words the glossary marks ambiguous are left out unless `--ambiguous`, and `--word` narrows the run to chosen words. Checks `docs/` and `tools/` by default, only the added lines with `--since REV`, or text on standard input (a commit message). Hits are leads, not defects. Reads no saves |
| `industry_chains.py [--content DIR] [--json] [--out DIR]` | Print the install's industry chains as Markdown tables (or JSON): recipes, boosters, climates per industry and per cargo, cargo classes, industries by rank. Reads the install's text files at run time (finds the Steam library itself, or pass `--content` with its `base/content` folder) and prints no install path. Warns on stderr where the industry and economy files disagree. See [docs/industry-chains.md](../docs/industry-chains.md) |
| `save_preview.py OUT_DIR SAVE.sav [...]` | Write each save's preview as a PNG, right way up |
| `mine_saves.py [--no-maps] OUT_DIR SAVE_OR_MODDIR [...]` | Mine many saves (or mod.io mod directories, including their editor `maps/`) into `OUT_DIR/<seed's first character>/<seed>/<id>-<name>/` (a save without a seed: `OUT_DIR/_noseed/<id>-<name>`; an old summary in another place is moved, not read again) and `OUT_DIR/index.csv`. Each folder gets `tf3-save-summary.json` from [mine_summary.py](mine_summary.py) and `terrain-map.svg`, the picture `terrain_map.py` draws with no options (so it follows that script's current defaults; `--no-maps` skips it; a save it cannot draw gets no picture and the reason goes into `.map_state.json`; a Giant map needs about 2.5 GB, so run at most `xargs -P4`). The two are rebuilt separately: the summary when the commit of `mine_summary.py` and the modules it imports differs from its `tools_commit`, the map when the commit of `terrain_map.py` and its imports differs from the one in `.map_state.json`, and either when the save changed (size or mtime). A change to `tf3save.py` rebuilds both; to `terrain_map.py`, `terrain_vector.py` or `street_edges.py` only the maps; to `mine_summary.py` only the summaries; a set with uncommitted changes (`-dirty`) is always rebuilt. Facts only, no local paths in the summaries |
| `mine_summary.py SAVE.sav` | Print one save's summary as JSON: header (including the map seed, the Map Size and Map Format as position and name, and the width and height), the cargo list and any cargo a mod adds, settings as `"3 (100%, default)"`, shown date, calendar and play speed, rank, counters, subsidies, town names (`towns`, null where they cannot be told, [docs/entity-names.md](../docs/entity-names.md#town-names-604)). `mine_saves.py` imports it. `tools_commit` in the summary is the commit of this script and its imports, not of the whole folder |
| `script_commits.py [SCRIPT]` | Print the files a script imports from this folder (its closure) and the last commit that changed any of them, `-dirty` if one has uncommitted changes; with no argument, the commit for the whole folder. `mine_saves.py` uses it to tell a summary rebuild from a map rebuild |
| `map_size_tables.py MINED_DIR [--extra SIZE,FORMAT,WxH ...]` | Print the two tables of [docs/map-sizes.md](../docs/map-sizes.md) from the summaries `mine_saves.py` wrote: all 40 `map.size` x `map.format` combinations with the width and height most saves have (blank where none was seen), then the saves whose dimensions differ from their settings, with the combination they fit and the mod.io title and id. `--extra` adds a game that is not in the folder (your own test). Reads no saves |

## Icons

`icons/industries/` holds one SVG per industry key (all 32 of the base game, named like the key, for example `icons/industries/saw_mill.svg`) for map plots. Each is a 64 x 64 solid pictogram drawn in `currentColor`, so the caller sets the colour with `color` or `fill`. They are our own drawings of plain objects (three wheat ears for `farm`, a pumpjack for `oil_well`, a tin for `food_factory`), picked to echo what the game's cargo icons show for each industry's products; none is traced from or copied out of the game's artwork. Like the code here, they are licensed MIT OR Apache-2.0. `icons/sunrise.svg` and `icons/sunset.svg` are the compass markers of `industry_compass.py`.

`icons/compass_rose.svg` is a standalone 64 x 64 compass rose (north an arrow, E, S and W on short arms), drawn in `currentColor` with bold sans-serif letters, so the letters take whatever sans-serif font the viewer has. It comes from `rose()` in `industry_compass.py` (scale 1.8, centre 32, 32.4), the same drawing as the rose in the corner of each compass plot.

## Editor setup

VS Code shows an "untrusted schema" warning on the `$schema` line of the summaries. How to clear it: [docs/developer/vscode-schema.md](../docs/developer/vscode-schema.md).

## Using them on other people's saves

Previews and saves belong to the people who made them. The scripts read them on your machine; do not republish their output without checking. The summaries from `mine_saves.py` hold only facts (version, sizes, counts) plus the catalog name, author and link that mod.io already shows publicly.

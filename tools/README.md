# Tools

Small read-only Python scripts used to check the notes in `docs/`. They are reference code, not a supported product: no releases, no promise they work on your saves. Bug reports with evidence (format version, what you saw) are very welcome. We aren't taking feature requests for the scripts, sorry.

Python 3.14 or later, standard library only by default (older Python works with the `zstandard` package installed). The scripts that do image work or OCR (`town_centre.py`, `shot_place.py`, `screenshot_index.py`) also use numpy, Pillow or the `tesseract` program, all permissively licensed, loaded or run only by the commands that need them, none bundled.

None of these scripts write a save. To look at an SVG a script wrote (a browser for a person, `rsvg-convert` for a session), see [docs/developer/tooling.md](../docs/developer/tooling.md). For editing, see [tf3-save-editor](https://github.com/TBK/tf3-save-editor).

| Script | What it does |
|---|---|
| `tf3save.py` | Shared code: zstd helpers, the empty trailing frame, temperate cargo ids, `scan_records` (the town record scan), `cargo_entries` and `cargo_list` (the save's own cargo list, which gives the cargo ids), the calendar speed field and day table, a Lua value reader and `script_state(stream, path)`, and the New Game option labels (`setting_label`). Imported by the others |
| `save_header.py SAVE.sav [...]` | Print a save's header: version, start year, map size, money, counter, preview, mods, resources, a few settings. Importable as `read_header(path)` |
| `calendar_speed.py SAVE.sav [...]` | Print the calendar speed (`millisPerDay`), play speed and current day stored in a save. Importable as `tf3save.find_game_speed(stream)` and `find_day_table(stream)` |
| `journal.py SAVE.sav` | Find the player's money journal by its place after the edge-addon name table (a search by the balance bytes for the oldest format, which has no table) and print how much the game was played: bookings, first and last play booking, `play_periods` (periods of 1,461,000 clock units from the first play booking's period to the last's), `active_periods`, `income_periods`, `income_total`. Starting capital and loan bookings are not play. Importable as `play_summary(data, header_money)`. Follows the finder in tf3-save-editor's `journal.rs` ([THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)); [docs/finances.md](../docs/play-length.md) |
| `items_lists.py SAVE.sav (--cargo ID \| --list REGEX) [--periods N]`, `--table LABEL=OFFSET:LIST ...`, `--entries OFFSET:LIST` | Read the `items*` statistics lists ([docs/statistics-lists.md](../docs/statistics-lists.md)): per group, each matching list's total, last entry time (and how many 1,461,000-unit periods before the save's clock), and its change in each of the last N periods with trailing zeros kept, so a stage that stopped shows as zeros; a per-period table across named lists; one list's entries. `--stream` takes an already decompressed stream. Offsets are stream offsets and move between saves; groups are matched by figures, since their owner is not known. Used in [docs/analysis-examples/](../docs/analysis-examples/CLAUDE.md) |
| `notifications.py SAVE.sav [--type REGEX] [--since CLOCK] [--last N] [--open] [--json]`, `--summary`, `--lines` | List the entries of the notifications state ([docs/notifications.md](../docs/notifications.md)), oldest first: id, clock, type, flags (dismissed, expired, tracked, persisting), entity ids, the names kept in `simParams`, and the other params. `--summary` counts entries per type and the bookkeeping tables; `--lines` lists the line entities that `line_warning` entries name (entity, `lineName`, whether the line is a key of `line2problemTimestamp`, `lineProblem`, `lineIssues`). `--stream` takes an already decompressed stream. Importable as `read_notifications(data)` and `entries(state)`. A string that looks like a path is masked. Used in [docs/analysis-examples/](../docs/analysis-examples/CLAUDE.md) |
| `town_states.py SAVE.sav [...]` | Print the per-town rating state from the `townStates` table |
| `town_places.py SAVE.sav [--export towns-export.lua] [--json] [--stream]` | Name and place every live town from the entity table ([docs/town-places.md](../docs/town-places.md)): entity id, name slot and name, town record row, building and parcel counts, and the mean of its parcels' centres with their spread. `--export` adds the distance to the map editor's Towns export position for the same name. Importable as `town_places(data)`, `find_entity_table(data)`, `read_entities(data, start, n)`, `names_table(data, ents)`, `line_count(ents, name_type)`, `town_table_header(...)` and `entity_summary(data, first_record)`, which `mine_summary.py` uses. About 15 to 50 s on a 575 MB to 1.2 GB stream |
| `street_edges.py SAVE.sav [--near X,Y,R] [--type REGEX] [--nodes] [--ids] [--json]`, `--diff OLD NEW` | List the street edges ([docs/road-network.md](../docs/road-network.md)): end node ids, end positions, street or track type and length per edge, or per node; `--ids` adds each edge's entity id where the strip table has an entry; `--diff` compares two saves and prints the edges added, removed or changed. Importable as `read_edges(data)` (each edge also has its tangents `t0`, `t1`; `edge_bezier(e)` gives the centre line as four Bezier control points, `bezier_point(c, t)` a point on it and `edge_is_curved(e)` whether it leaves its chord), and `read_free_ids(data)` (the set of the save's free entity ids, or None; [docs/town-leftovers.md](../docs/town-leftovers.md)) |
| `edge_speeds.py SAVE.sav [--near X,Y,R] [--family street\|track\|all] [--curved] [--accel A] [--json]` | Print each street (or track) edge's stored speed (the type's, from the lane data) and the number the speed layer shows on a bend, by the rule in [docs/road-speeds.md](../docs/road-speeds.md): the lower of the stored speed and 3.6 * sqrt(A / largest curvature) km/h, A 2.5 m/s^2. Read off about 60 labels of one game, road and rail; treat bends as +-1 km/h |
| `lane_paths.py SAVE.sav [--near X,Y,R] [--family track\|street\|all] [--nodes] [--json]` | Read the save's path records ([docs/lane-paths.md](../docs/lane-paths.md)): per edge the game's own arc length and the bend speed it saved (the speed layer's number before rounding) next to the value `edge_speeds.py`'s rule gives, and with `--nodes` the connections inside each node (slots, length, stored speed; a rail crossing with Double Slip Switch on has two more). Importable as `read_paths(data, edges)` and `read_node_links(data, region)`. About 8 s on a Giant save |
| `industry_compass.py SAVE.sav OUT.svg [--top N] [--across N] [--down N] [--no-sun]` | Test the compass words in industry and building names ([docs/compass.md](../docs/compass.md)): for each name ending in North, South, East or West, count the same-kind industries, depots and boathouses near that town in the quarter the word names, under each of eight frames of x and y, and draw one picture per town (2 across and 3 down by default, the most telling towns first), with the surest N names (4 by default) drawn, the named industries in blue and the other same-kind ones hollow, against the town's centre (the game's frame, orange sunrise and sunset icons from `icons/`). The town centre is the mean of its street nodes. A PNG is a browser screenshot of the SVG |
| `parcels.py SAVE.sav [--near X,Y,R] [--json] [--points]`, `parcels.py --diff OLD.sav NEW.sav [--near X,Y,R]` | List the parcel table ([docs/parcels.md](../docs/parcels.md)): without options a summary (where the table starts, parcels, street edges, faces, how often each flag word and tail value occurs); `--near` one line per parcel with its first face near the point (table index, street edge id, side, position along the edge, the flag word of each face, centre of the first face); `--json` the same as JSON, `--points` with the corners of every face. `--diff` compares two saves of one game by table index and prints the parcels whose flag words changed, the number of parcels appended and, with `--near`, only those near a point. Importable as `read_parcels(data)`. `--stream` reads an already decompressed stream. Takes under a second on a 150 MB stream. The parcel's own entity id is not in the table, so it prints the index; the entity table maps an id to it ([docs/entity-table.md](../docs/entity-table.md)) |
| `town_centre.py SAVE.sav --list`, `town_centre.py SAVE.sav --town X,Y SHOT.png [...] [--out DIR] [--json] [--scales A,B,..] [--pitches A,B,..] [--thorough] [--min-score S] [-j N]` | Find a town's centre from a series of screenshots of its name label ([docs/town-centre.md](../docs/town-centre.md)): registers each picture to the save's street edges (heading, zoom, pitch, perspective), maps the label's bottom-edge middle to metres, and fits a circle and a label-at-a-height model through the series. `--list` names the town street clusters to pick `--town` from. Needs numpy and Pillow; reads a save and pictures, writes only into `--out` (a picture and a JSON) |
| `shot_place.py SAVE.sav SHOT.png --vehicle PX,PY[,DEG] --vehicle PX,PY[,DEG] [...] --hint X,Y[,R] [--class PREFIX] [--in-frame X,Y] [--covered X0,Y0,X1,Y1] [--ui] [--scale-range A,B] [--map MAP.png] [--pick N] [--no-refine] [--pixel PX,PY] [--badges] [--project PREFIX] [--out DIR] [--json]` | Place a screenshot on the map from the vehicles it shows. Name two or more vehicles in the full-size picture (pixel position, optionally the direction of the long axis); the script pairs the first two with every ordered pair of the save's vehicles of that class (default ships) inside the hint circle, solves scale and heading from each, ranks them (heading error, the third and later vehicles, save vehicles in the frame that are not named, except those under the game's window: `--ui` covers the building window and the two bars, `--covered` a box of your own) and prints the runners-up so an ambiguous picture shows. It then adds the two perspective terms of a homography, searched against the map's coastline with the two vehicles held exactly on their places in the save, and prints the view centre, the scale change from bottom to top and the map point under any `--pixel`. `--badges` reads the `n/m` load badges over vehicles (tesseract, three passes over the picture, because the small and coloured ones are missed by any one) and, with `--project PREFIX` (for example `vehicle/`), names the three save vehicles the fit puts nearest each badge: a badge's text sits 40 to 120 px from its vehicle, and a tram's badge was within 16 px of its power car. `--out` writes a blend (the map over the picture) and a JSON. The fit is a plane at water level: things above it (viaducts, roofs) are shifted by the camera's tilt and will not line up. Takes the map picture from `--map` (a `tf3map --png --mpp 1` crop, whose view record gives the frame) or makes one itself with `tf3map` (about a second). Needs numpy and Pillow (and the `tesseract` program for `--badges`) and imports `town_centre.py`; reads a save, a picture and the map picture, writes only into `--out`. Tuned on one temperate daytime picture. Workflow: `.claude/skills/shot-place/SKILL.md` |
| `screenshot_index.py --work DIR [--shots DIR] [--saves-dir DIR] [--date YYYYMMDD] [--hud-engine tesseract\|rapidocr] [--no-nice] ocr\|todo\|sheets\|build\|check\|hud`, `find TERM ...`, `classify [TERM ...]`, `shrink-loads [--apply]` | Index a player's screenshots (private working files in `--work`, a folder git ignores). `ocr` reads the text off every shot with tesseract (window titles, `Name (123)` town labels, the game date and the bottom bar's account, earnings, people delivered and cargo delivered; paths and the default company name are masked); `find` searches it; `build` writes `INDEX.md` from hand-kept `labels.tsv` (ranges of shots, because shots come in clusters): UTC times, what each cluster shows, the saves written around it, a topic table; `todo` lists clusters no label covers, each with a hint whether its first shot looks like the same static view as the shot before (edge correlation of thumbnails, numpy and Pillow; 0.5 and up reads as a continuation of a long watch; also the OCR lines the two share that few shots have, the HUD date and, on 3840x2160 frames, the CEO experience bar, which only rises within a session); `check` lists label facts the OCR did not see; `hud` writes `hud.csv`; `sheets` makes contact sheets. `ocr` also marks the game's loading screens by their layout (black bars, picture between, save name centred at the top, percentage or Start Game at the lower right; found by pixels, so any loading picture works): `build` lists them in a Loading screens section with the title, the progress and whether a save of that name is a game or an editor save, and `todo` skips them. Finds the screenshot folder (`~/Pictures/Screenshots`, shots filed below its `tf3/YYYY-MM-DD/` day folders are found too) and the game's save folders (the usual Steam places, app 3493540) by itself; `--shots` and `--saves-dir` override. Needs the `tesseract` program and Pillow for `ocr` and `sheets` only (the rest is standard library). `--hud-engine rapidocr` reads the bottom bar with the `rapidocr` and `onnxruntime` packages (Apache-2.0 and MIT, about 370 MB with OpenCV and numpy, models inside the wheel; `pip install rapidocr onnxruntime`), imported only with that option. It runs itself at nice 19 and idle I/O (`--no-nice` turns that off). Workflow: `.claude/skills/screenshot-index/SKILL.md`  `classify` buckets every shot by the UI its text shows (category and subcategory: loading screen, mod hub, save's Mods tab, save settings, depot-retrofits mod panel, finances, map layer and so on) and records full screen or cropped (picture size against the most common size) in `categories.csv`; `build` adds a Find by category table. Rules are `CATEGORY_RULES` in the script, tuned by hand; a scaled frame of the common shape counts as full screen. `shrink-loads` lists the load cards still kept as PNG, and with `--apply` replaces each with a JPG (quality 85, 1080 rows, same name stem and file times; Pillow), the only command that writes into the screenshot folder.|

| `mine_saves.py [--no-maps] [--no-nice] [--summary rust\|python] [--summary-bin BIN] [--tf3map BIN] [--game DIR] [--mods DIR] OUT_DIR SAVE_OR_MODDIR [...]` | Mine many saves into `OUT_DIR/<corpus>/<seed's first character>/<seed>/<leaf>/` (a save without a seed: `OUT_DIR/<corpus>/_noseed/<leaf>`; an old summary in another place is moved, not read again) and `OUT_DIR/index.csv` (last column `corpus`). Facts only, no local paths in the summaries. It runs itself at nice 19 and idle I/O (`--no-nice` turns that off), and the drawer inherits it |

## Icons

`icons/industries/` holds one SVG per industry key (all 32 of the base game, named like the key, for example `icons/industries/saw_mill.svg`) for map plots. Each is a 64 x 64 solid pictogram drawn in `currentColor`, so the caller sets the colour with `color` or `fill`. They are our own drawings of plain objects (three wheat ears for `farm`, a pumpjack for `oil_well`, a tin for `food_factory`), picked to echo what the game's cargo icons show for each industry's products; none is traced from or copied out of the game's artwork. Like the code here, they are licensed MIT OR Apache-2.0. `icons/sunrise.svg` and `icons/sunset.svg` are the compass markers of `industry_compass.py`.

`icons/anchor_large.svg` and `icons/anchor_small.svg` are two 64 x 64 anchor pictograms in `currentColor`, for ships and water stations: the large one is a vertical stock anchor filling the frame, the small one a tilted anchor with two flat blades, drawn about 0.72 times the size so the two tell apart at 16 px. Our own drawings.

`icons/compass_rose.svg` is a standalone 64 x 64 compass rose (north an arrow, E, S and W on short arms), drawn in `currentColor` with bold sans-serif letters, so the letters take whatever sans-serif font the viewer has. It comes from `rose()` in `industry_compass.py` (scale 1.8, centre 32, 32.4), the same drawing as the rose in the corner of each compass plot.

## Using them on other people's saves

Previews and saves belong to the people who made them. The scripts read them on your machine; do not republish their output without checking. The summaries from `mine_saves.py` hold only facts (version, sizes, counts) plus the catalog name, author and link that mod.io already shows publicly.

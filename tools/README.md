# Tools

Small read-only Python scripts used to check the notes in `docs/`. They are reference code, not a supported product: no releases, no promise they work on your saves. Bug reports with evidence (format version, what you saw) are very welcome. We aren't taking feature requests for the scripts, sorry.

Python 3.14 or later, standard library only by default (older Python works with the `zstandard` package installed). The scripts that do image work or OCR (`town_centre.py`, `shot_place.py`, `screenshot_index.py`) also use numpy, Pillow or the `tesseract` program, all permissively licensed, loaded or run only by the commands that need them, none bundled.

None of these scripts write a save. To look at an SVG a script wrote (a browser for a person, `rsvg-convert` for a session), see [docs/developer/tooling.md](../docs/developer/tooling.md). For editing, see [tf3-save-editor](https://github.com/TBK/tf3-save-editor).

Imported by the others |
| `save_header.py SAVE.sav [...]` | Print a save's header: version, start year, map size, money, counter, preview, mods, resources, a few settings. Importable as `read_header(path)` |
| `calendar_speed.py SAVE.sav [...]` | Print the calendar speed (`millisPerDay`), play speed and current day stored in a save. Importable as `tf3save.find_game_speed(stream)` and `find_day_table(stream)` |
| `journal.py SAVE.sav` | Find the player's money journal by its place after the edge-addon name table (a search by the balance bytes for the oldest format, which has no table) and print how much the game was played: bookings, first and last play booking, `play_periods` (periods of 1,461,000 clock units from the first play booking's period to the last's), `active_periods`, `income_periods`, `income_total`. Starting capital and loan bookings are not play. Importable as `play_summary(data, header_money)`. Follows the finder in tf3-save-editor's `journal.rs` ([THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)); [docs/finances.md](../docs/play-length.md) |
| `items_lists.py SAVE.sav (--cargo ID \| --list REGEX) [--periods N]`, `--table LABEL=OFFSET:LIST ...`, `--entries OFFSET:LIST` | Read the `items*` statistics lists ([docs/statistics-lists.md](../docs/statistics-lists.md)): per group, each matching list's total, last entry time (and how many 1,461,000-unit periods before the save's clock), and its change in each of the last N periods with trailing zeros kept, so a stage that stopped shows as zeros; a per-period table across named lists; one list's entries. `--stream` takes an already decompressed stream. Offsets are stream offsets and move between saves; groups are matched by figures, since their owner is not known. Used in [docs/analysis-examples/](../docs/analysis-examples/CLAUDE.md) |
| `notifications.py SAVE.sav [--type REGEX] [--since CLOCK] [--last N] [--open] [--json]`, `--summary`, `--lines` | List the entries of the notifications state ([docs/notifications.md](../docs/notifications.md)), oldest first: id, clock, type, flags (dismissed, expired, tracked, persisting), entity ids, the names kept in `simParams`, and the other params. `--summary` counts entries per type and the bookkeeping tables; `--lines` lists the line entities that `line_warning` entries name (entity, `lineName`, whether the line is a key of `line2problemTimestamp`, `lineProblem`, `lineIssues`). `--stream` takes an already decompressed stream. Importable as `read_notifications(data)` and `entries(state)`. A string that looks like a path is masked. Used in [docs/analysis-examples/](../docs/analysis-examples/CLAUDE.md) |
| `town_states.py SAVE.sav [...]` | Print the per-town rating state from the `townStates` table |
| `street_edges.py SAVE.sav [--near X,Y,R] [--type REGEX] [--nodes] [--ids] [--json]`, `--diff OLD NEW` | List the street edges ([docs/road-network.md](../docs/road-network.md)): end node ids, end positions, street or track type and length per edge, or per node; `--ids` adds each edge's entity id where the strip table has an entry; `--diff` compares two saves and prints the edges added, removed or changed. Importable as `read_edges(data)` (each edge also has its tangents `t0`, `t1`; `edge_bezier(e)` gives the centre line as four Bezier control points, `bezier_point(c, t)` a point on it and `edge_is_curved(e)` whether it leaves its chord), and `read_free_ids(data)` (the set of the save's free entity ids, or None; [docs/town-leftovers.md](../docs/town-leftovers.md)) |
| `edge_speeds.py SAVE.sav [--near X,Y,R] [--family street\|track\|all] [--curved] [--accel A] [--json]` | Print each street (or track) edge's stored speed (the type's, from the lane data) and the number the speed layer shows on a bend, by the rule in [docs/road-speeds.md](../docs/road-speeds.md): the lower of the stored speed and 3.6 * sqrt(A / largest curvature) km/h, A 2.5 m/s^2. Read off about 60 labels of one game, road and rail; treat bends as +-1 km/h |
| `lane_paths.py SAVE.sav [--near X,Y,R] [--family track\|street\|all] [--nodes] [--json]` | Read the save's path records ([docs/lane-paths.md](../docs/lane-paths.md)): per edge the game's own arc length and the bend speed it saved (the speed layer's number before rounding) next to the value `edge_speeds.py`'s rule gives, and with `--nodes` the connections inside each node (slots, length, stored speed; a rail crossing with Double Slip Switch on has two more). Importable as `read_paths(data, edges)` and `read_node_links(data, region)`. About 8 s on a Giant save |
| `industry_compass.py SAVE.sav OUT.svg [--top N] [--across N] [--down N] [--no-sun]` | Test the compass words in industry and building names ([docs/compass.md](../docs/compass.md)): for each name ending in North, South, East or West, count the same-kind industries, depots and boathouses near that town in the quarter the word names, under each of eight frames of x and y, and draw one picture per town (2 across and 3 down by default, the most telling towns first), with the surest N names (4 by default) drawn, the named industries in blue and the other same-kind ones hollow, against the town's centre (the game's frame, orange sunrise and sunset icons from `icons/`). The town centre is the mean of its street nodes. A PNG is a browser screenshot of the SVG |
| `parcels.py SAVE.sav [--near X,Y,R] [--json] [--points]`, `parcels.py --diff OLD.sav NEW.sav [--near X,Y,R]` | List the parcel table ([docs/parcels.md](../docs/parcels.md)): without options a summary (where the table starts, parcels, street edges, faces, how often each flag word and tail value occurs); `--near` one line per parcel with its first face near the point (table index, street edge id, side, position along the edge, the flag word of each face, centre of the first face); `--json` the same as JSON, `--points` with the corners of every face. `--diff` compares two saves of one game by table index and prints the parcels whose flag words changed, the number of parcels appended and, with `--near`, only those near a point. Importable as `read_parcels(data)`. `--stream` reads an already decompressed stream. Takes under a second on a 150 MB stream. The parcel's own entity id is not in the table, so it prints the index |
| `town_centre.py SAVE.sav --list`, `town_centre.py SAVE.sav --town X,Y SHOT.png [...] [--out DIR] [--json] [--scales A,B,..] [--pitches A,B,..] [--thorough] [--min-score S] [-j N]` | Find a town's centre from a series of screenshots of its name label ([docs/town-centre.md](../docs/town-centre.md)): registers each picture to the save's street edges (heading, zoom, pitch, perspective), maps the label's bottom-edge middle to metres, and fits a circle and a label-at-a-height model through the series. `--list` names the town street clusters to pick `--town` from. Needs numpy and Pillow; reads a save and pictures, writes only into `--out` (a picture and a JSON) |
| `shot_place.py SAVE.sav SHOT.png --vehicle PX,PY[,DEG] --vehicle PX,PY[,DEG] [...] --hint X,Y[,R] [--class PREFIX] [--in-frame X,Y] [--covered X0,Y0,X1,Y1] [--ui] [--scale-range A,B] [--map MAP.png] [--pick N] [--no-refine] [--pixel PX,PY] [--badges] [--project PREFIX] [--out DIR] [--json]` | Place a screenshot on the map from the vehicles it shows. Name two or more vehicles in the full-size picture (pixel position, optionally the direction of the long axis); the script pairs the first two with every ordered pair of the save's vehicles of that class (default ships) inside the hint circle, solves scale and heading from each, ranks them (heading error, the third and later vehicles, save vehicles in the frame that are not named, except those under the game's window: `--ui` covers the building window and the two bars, `--covered` a box of your own) and prints the runners-up so an ambiguous picture shows. It then adds the two perspective terms of a homography, searched against the map's coastline with the two vehicles held exactly on their places in the save, and prints the view centre, the scale change from bottom to top and the map point under any `--pixel`. `--badges` reads the `n/m` load badges over vehicles (tesseract, three passes over the picture, because the small and coloured ones are missed by any one) and, with `--project PREFIX` (for example `vehicle/`), names the three save vehicles the fit puts nearest each badge: a badge's text sits 40 to 120 px from its vehicle, and a tram's badge was within 16 px of its power car. `--out` writes a blend (the map over the picture) and a JSON. The fit is a plane at water level: things above it (viaducts, roofs) are shifted by the camera's tilt and will not line up. Takes the map picture from `--map` (a `terrain_map.py --png --mpp 1` crop, whose view record gives the frame) or makes one itself (about a minute). Needs numpy and Pillow (and the `tesseract` program for `--badges`) and imports `town_centre.py`; reads a save, a picture and the map picture, writes only into `--out`. Tuned on one temperate daytime picture. Workflow: `.claude/skills/shot-place/SKILL.md` |
| `screenshot_index.py --work DIR [--shots DIR] [--saves-dir DIR] [--date YYYYMMDD] [--hud-engine tesseract\|rapidocr] ocr\|todo\|sheets\|build\|check\|hud`, `find TERM ...` | Index a player's screenshots (private working files in `--work`, a folder git ignores). `ocr` reads the text off every shot with tesseract (window titles, `Name (123)` town labels, the game date and the bottom bar's account, earnings, people delivered and cargo delivered; paths and the default company name are masked); `find` searches it; `build` writes `INDEX.md` from hand-kept `labels.tsv` (ranges of shots, because shots come in clusters): UTC times, what each cluster shows, the saves written around it, a topic table; `todo` lists clusters no label covers; `check` lists label facts the OCR did not see; `hud` writes `hud.csv`; `sheets` makes contact sheets. `ocr` also marks the game's loading screens by their layout (black bars, picture between, save name centred at the top, percentage or Start Game at the lower right; found by pixels, so any loading picture works): `build` lists them in a Loading screens section with the title, the progress and whether a save of that name is a game or an editor save, and `todo` skips them. Finds the screenshot folder (`~/Pictures/Screenshots`) and the game's save folders (the usual Steam places, app 3493540) by itself; `--shots` and `--saves-dir` override. Needs the `tesseract` program and Pillow for `ocr` and `sheets` only (the rest is standard library). `--hud-engine rapidocr` reads the bottom bar with the `rapidocr` and `onnxruntime` packages (Apache-2.0 and MIT, about 370 MB with OpenCV and numpy, models inside the wheel; `pip install rapidocr onnxruntime`), imported only with that option. Workflow: `.claude/skills/screenshot-index/SKILL.md` |
| `model_instances.py SAVE.sav [--near X,Y,R] [--prefix PATH] [--stream]` | List the model instances ([docs/models.md](../docs/models.md)) whose model path starts with `--prefix` (default `vehicle/`): slot, model, position and facing (the first row of the transform). Importable as `read_model_table(data)` and `read_instances(data, prefixes)`. Reads the whole stream (about 20 s for 700 MB). A vehicle's name and entity id are not next to its instance, so a vehicle is named by model and slot; the slot is only good within one save |
| `vehicle_counts.py SAVE.sav [--game DIR] [--models]` | Count a save's vehicle units by carrier (`road`, `tram`, `rail`, `water`, `air`), power (`powered`, `unpowered`, `unknown`) and load (`passenger`, `cargo`, `mixed`, `none`, `unknown`) from its `vehicle/` model instances, with the helicopters among the air units, the private cars as `ambient` and the number of models it could not classify; `--models` adds the count per model path. A base-game model is classified from the install's model file metadata (`base/content/vehicle/<folder>/<name>.zip`, read at run time, never stored; `--game DIR` names the install), a mod's model by its folder. Importable as `count_vehicles(data)` and `index_values(counts)`; about 20 to 90 s a save. Reads a save and the install, writes nothing; [docs/vehicle-classes.md](../docs/vehicle-classes.md) |
| `terrain_map.py OUT_DIR SAVE.sav [...] [--mpp M] [--crop X,Y,R] [--grid N] [--grid-lines auto\|none\|dots\|faint] [--grid-dot-step M] [--png \| --raster] [--contour M] [--index N] [--no-bands] [--tolerance M] [--no-grid] [--no-industries] [--rose WHERE] [--rose-size M] [--north game\|sun] [--game DIR] [--no-network] [--keep-dead] [--depots] [--stations] [--coverage] [--industries] [--industry-size M]` | Draw the heightmap with the street-edge table's roads and rails on top, a bent edge as the curve its stored tangents give and a straight one as a line ([docs/terrain.md](../docs/terrain.md#drawing-the-map)). An edge with an end node in the save's free-id list (a deleted town's or road's leftover, [docs/town-leftovers.md](../docs/town-leftovers.md)) is left out unless `--keep-dead` is given; the run prints how many were dropped. The default output is an SVG: the terrain (height ramp, hill shading, water) as an embedded PNG, and the roads (grey) and rails (red) as vector paths in map metres, in layers a page script can toggle: every layer is a `g.layer` with its id in `data-layer`, roads and rails have a sublayer per type with one `<path data-a data-b>` per edge, vehicles one sublayer per class with a `<g class="vehicle" data-slot data-model data-class>` each, labels and end nodes their own sublayers (the full list is in the script's docstring). Line widths are in metres, so they scale with the terrain in any viewer, and as wide as the street or track type's profile (the sum of its lanes' widths, a small town street 16 m, a track 4 m, read from the install's templates at run time, with 16 and 4 m for a type it lacks; `--game DIR` names the install, otherwise the usual Steam folders are tried; `--min-width M` sets a floor in metres so a whole-map picture keeps its tracks visible). Output names have no spaces, and a crop's name carries its centre and radius. The SVG's `<metadata>` holds one `tf3map:view` element (namespace `urn:tf3-save-format:terrain-map:1`) with the save's file name, the map size, the metres per pixel, the map point at the picture's top-left corner, the x and y range it covers, the crop and the grid step, and which run made it (`generator`, `generator-commit`, the last commit that changed a `tools/*.py` with `-dirty` if one has uncommitted changes, and `generated-utc`; a setting left at its default is not recorded, only one changed from it), so a picture can be turned back into map coordinates without its command line. `--png` writes one flat shaded PNG instead, with the same view record in an `iTXt` chunk `tf3map:view` (a UTF-8 JSON object with the SVG attribute names, `north` included). The terrain is vector by default ([terrain_vector.py](terrain_vector.py); output `...-terrain.svg`, `--mpp` default 8, 4 on a crop): sublayers `land`, `bands` (a path per `--contour` metres of height, default 20, filled from a height ramp, each covering all ground from there up), `water` (lakes, sea and rivers as one even-odd path, from the contour at the water level) and `contours-minor` / `contours-index` (one `<path data-height>` per level, every `--index`th heavier, default 5, thinned to `--tolerance`); `--no-bands` leaves the fills out. There is no hill shading, so the file is hundreds of kilobytes where a raster one is megabytes; roads, rails, vehicles and grid go on top as before. A compass rose (a white circle, black arrow and E, S, W arms, in the shape of `icons/compass_rose.svg`) sits in its own top `compass` layer, lower right by default: `--rose lower-left|upper-left|upper-right|off|X,Y` moves or removes it, `--rose-size` sets its diameter (250 m, at most an eighth of the picture's short side), and its arms follow `--north`. `--raster` draws the old terrain, a shaded PNG embedded in the SVG (`...-terrain-raster.svg`). `--mpp` is the terrain's metres per pixel, a multiple of 4, default 4 (the grid's own spacing); a picture over 64 million pixels is refused until `--mpp` is raised (the 20 x 41 km Giant map is 52 million at 4 m: 42 s, 1.3 GB, an 81 MB SVG). The SVG has a grid by default, major marks only: a large cross where the lines meet, a dotted line and a label at each, every third of the picture's shorter side rounded down to 1, 2 or 5 times a power of ten (a whole map at least 1000 m, so Tiny and Small get 1 km, Medium and Large 2 km, Giant 5 km; a `--crop` has no floor), `--no-grid` leaves it out. `--grid N` (SVG only) adds minor marks, for fine work, in the same `grid` layer, so a place seen in the picture can be turned into `--crop` coordinates: a small violet cross where the lines at every multiple of N metres of map x and y would meet (sublayer `grid-minor`), a larger one where two 1000 m lines meet, a line of darker dots at each multiple of 1000 m (both in `grid-major`; every dot and small cross arm is one pixel wide, a large cross's arm 1.5), and coordinate labels along the top and left in a `grid-labels` layer over everything (a label is left out, never moved, when it would run off the right edge or a left one would sit in the top row). The marks are violet because no terrain, road or rail colour is near it, and crosses and dots do not read as roads the way solid lines do. `--grid-lines none` leaves out the dotted 1000 m lines, and so does the default `auto` on a picture of 1 m per pixel or finer, where a dot is a speck and the crosses are enough; `--grid-lines dots` also draws the minor lines as round dots every `--grid-dot-step` metres (default 25, never closer than 10 pixels, and nudged so a whole number fit between two crosses; a small cross's arm is a sixth of the gap, a larger cross's 0.4 of it, and the 1000 m lines carry twice as many dots; `--mpp 2` on a crop allows 25 m), and `--grid-lines faint` as thin faint solid lines. `--label A>B[=TEXT]` (repeat; SVG only) adds a `labels` layer naming just the edges asked for by their end node ids in hex (`2a619>342aa`), above the vehicles, each in its own light colour (the text's halo) with a white dot, black ring, at both ends (a node shared by two labelled edges gets a dot of two halves, one in each edge's colour, the half toward its edge); `--edge-ids` adds the edge's entity id where the strip table has one. `--vehicles` (needs `--crop`) adds a `vehicles` layer: each `vehicle/` model instance as a five-sided shape (a rectangle with a pointed front end, white outline, mid-dark grey for trains and trams; interior dark orange for a train engine, light orange for its trailing cars, purple tram, dark blue truck, dark green bus, dark grey ship, mid grey car), sized by class, with text only where `--name SLOT=TEXT` gives it (a default name is shortened: `Road Vehicle 279` is `RV279`, `Train 58` `RR58`, `Ship 106` `S106`, `Tram 62` `TRM62`, `Aircraft 6` `AIR6`) (the run prints every instance drawn with its slot, so a second run can name them). `--depots` (SVG only) adds `maintenance-buildings`, `road-depots`, `tram-depots`, `rail-maintenance-buildings`, `rail-depots`, `ship-maintenance-buildings`, `ship-depots` and `boathouses` layers: each building as its ground face (opaque, one tone per carrier, provisional: ship dark brown, rail dark grey, road lighter grey, tram lightest grey, a maintenance building a step darker than its depot; the stations' black outline, no marks inside; a boathouse of the Boathouse mod has no face, only a dot), placed from the instance's origin and facing ([docs/models.md](../docs/depots.md)); `--coverage` adds a `coverage` layer under the roads with a dashed circle per building at the script's catchment radius (sublayers per kind, `data-pool` and `data-modes` on each; each circle is drawn round the origin, though a ship depot's own ring was seen 0 to 66 m off it, [docs/depots.md](../docs/depots.md)). Both read the footprint, radius and pool from the install's `depots/road.zip` at run time (without an install nothing is drawn), need no `--crop`, and leave out aircraft maintenance; the boathouse's radius and pool are read from the mod's folder (`--mods DIR`, default the usual mod.io places), and the free Boathouse asset shares its model. `--stations` (SVG only) adds a `stations` layer for the platforms and buildings of water, rail and street (bus and tram) stations, a sublayer per group (`station-water-decks`, `-water-buildings`, `-rail-platforms`, `-rail-buildings`, `-street-platforms`, `-street-buildings`; brown, grey and light grey, provisional): each piece as the box of its model's `boundingInfo` in the install's `stations/*.zip` (read at run time, never stored), placed from the instance's origin and facing, a piece with thin edge pieces as its cell that holds them too, with each group's outer edge at an industry's outline width and no line where two boxes touch, with the street groups in a `stations-street` layer above the roads, where a bus, tram or cargo station also gets a `station-street-ground` fill and a `station-street-borders` outline (the union of its platform tiles and centre, path and entrance pieces with gaps up to 6 m closed, a little under the game's own border line), plus a `station-landings` sublayer that stamps a very dark grey anchor (`icons/anchor_small.svg` or `anchor_large.svg`, no disc, moved off the pier edge and turned so its ring points at the deck) on each landing marker, small or large by its model; railings, roofs, lamps, paths, entrances and the freight add-ons are left out ([station-pieces.md](../docs/station-pieces.md)), and no `--crop` is needed. `--industries` (SVG only, on by default; `--no-industries` leaves it out) adds an `industries` layer: each industry as a white disc with a grey border and its icon from `icons/industries/` in dark grey, (a sublayer per key, `<g class="industry" data-slot data-key data-x data-y>` each). A badge with a footprint is 0.4 of the polygon's shorter side across and sits on the polygon's centroid (the origin when the centroid is outside it); one without is 64 m on the origin; `--industry-size M` sets every badge's diameter (the icon and border scale with it). Under the badges each land industry's footprint is drawn (its script's `ground_face` polygon, read from the install at run time, placed from the origin and facing: dark purple outline, translucent light purple fill; [docs/models.md](../docs/models.md#industry-footprints-the-ground-face-from-the-industrys-script)); the fishing grounds and sand excavator get an outline measured off the game's Towns layer (`MEASURED_FACES`, about 2 m); the oil platform gets a stand-in for its tinted deck (a box of its `oil_platform_sm` model's size with the helipad's octagon and the big crane's boom) and a circle on each docking station (`MEASURED_DISCS`); a mod's industry gets the badge alone, which may overhang a small industry. A badge is a few pixels on a whole-map picture, so zoom in. `--zoom N` opens the SVG N times larger. `--crop X,Y,R` draws only the square of half-width R metres around a map point, and with it `--mpp` may be 1 or 2 (terrain interpolated). Writes only the picture. A sample picture: [docs/samples/terrain-map-area-labelled-6425796.svg](../docs/samples/terrain-map-area-labelled-6425796.svg) |
| `terrain_vector.py` (library, no command line) | Marching-squares contours of a heightmap grid for `terrain_map.py`: `level_rings` (closed rings round the ground below the water level and below every multiple of a step above it, the grid padded so rings close at the picture's edge, for even-odd filling), `split_at_border` (a ring back into open height lines), `simplify` (Douglas-Peucker, tolerance in metres) and `path_data` (SVG path text, tenths of a metre). ## Icons

`icons/industries/` holds one SVG per industry key (all 32 of the base game, named like the key, for example `icons/industries/saw_mill.svg`) for map plots. Each is a 64 x 64 solid pictogram drawn in `currentColor`, so the caller sets the colour with `color` or `fill`. They are our own drawings of plain objects (three wheat ears for `farm`, a pumpjack for `oil_well`, a tin for `food_factory`), picked to echo what the game's cargo icons show for each industry's products; none is traced from or copied out of the game's artwork. Like the code here, they are licensed MIT OR Apache-2.0. `icons/sunrise.svg` and `icons/sunset.svg` are the compass markers of `industry_compass.py`.

`icons/anchor_large.svg` and `icons/anchor_small.svg` are two 64 x 64 anchor pictograms in `currentColor`, for ships and water stations: the large one is a vertical stock anchor filling the frame, the small one a tilted anchor with two flat blades, drawn about 0.72 times the size so the two tell apart at 16 px. Our own drawings.

`icons/compass_rose.svg` is a standalone 64 x 64 compass rose (north an arrow, E, S and W on short arms), drawn in `currentColor` with bold sans-serif letters, so the letters take whatever sans-serif font the viewer has. It comes from `rose()` in `industry_compass.py` (scale 1.8, centre 32, 32.4), the same drawing as the rose in the corner of each compass plot.

## Editor setup

VS Code shows an "untrusted schema" warning on the `$schema` line of the summaries. How to clear it: [docs/developer/vscode-schema.md](../docs/developer/vscode-schema.md).

## Using them on other people's saves

Previews and saves belong to the people who made them. The scripts read them on your machine; do not republish their output without checking. The summaries from `mine_saves.py` hold only facts (version, sizes, counts) plus the catalog name, author and link that mod.io already shows publicly.
